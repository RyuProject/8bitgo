# public/bios/ —— 平台 BIOS 放这里

有些平台不给 BIOS 根本起不来，这跟 ROM 对不对没关系：

| 平台 | 需要的文件 | 说明 |
|---|---|---|
| 街机（Neo Geo 系） | `neogeo.zip` | 拳皇、合金弹头、侍魂等 MVS/AES 游戏必须要；CPS1/CPS2（街霸这类）不需要 |
| PS1 | `scph5501.bin` 等 | 多数核心可以不用，但用真 BIOS 兼容性更好 |

## 怎么用

1. 把文件按上面的名字丢进这个目录，例如 `public/bios/neogeo.zip`
2. 后台 →「ROM 存储」→「平台 BIOS」，在对应平台的输入框里填 **`/bios/neogeo.zip`**（以 `/` 开头 = 站点根目录下的路径）
3. 重新 `npm run build`，`public/` 里的东西会被复制进 `dist/client/`，然后由站点直接提供

也可以不放这里，改成上传到对象存储（R2）—— 后台那一栏的「上传文件」按钮走的就是那条路，填的是对象 key 而不是路径。两种都行，区别只是文件放在哪。

## 注意

- **这个目录里的文件不进 git**（见根目录 `.gitignore`），和 `public/ruffle`、`public/jsdos`、`public/webretro` 一个待遇。
  BIOS 通常是有版权的商业固件，一旦提交进仓库历史就很难彻底删干净；仓库如果是公开的，那等于对外分发。
- 正因为不进 git，**构建机上也得有这个文件**。你在本地放了、服务器上没放，线上就会缺。
  部署时要么把它一起同步到服务器再 `npm run build`，要么干脆走对象存储那条路（那样只有一份，谁都不用管）。
- 文件本身的来源合法性由你自己把关。

## 怎么确认文件是对的

后台那一栏会显示「实际地址」，点开能下载就说明路径对了。
真要校验内容，用 FBNeo 的白名单比对 CRC32 —— 它在 FBNeo 源码的
`src/burn/drv/neogeo/d_neogeo.cpp` 里，写着每个可接受的 BIOS 文件及其哈希。
