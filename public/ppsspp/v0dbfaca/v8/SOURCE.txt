=====================================

Upstream fork: https://github.com/root-hunter/ppsspp-wasm
Pinned commit: 0dbfaca62a8a924abc2c5dd5dd0733b668e5e68a
Original project: https://github.com/hrydgard/ppsspp

8BitGo applies vendor/ppsspp/patches/0001 through 0010 before building. They add strict
HTTP Range streaming, pthread-safe WebGL and audio, the save/control bridge, and the
adaptive browser performance profile, plus measured CHD cold-start and preload-data
optimizations. The v8 browser bridge keeps every game at native internal resolution with
buffered framebuffer effects, and mounts the persistent Memory Stick outside both remote
and local disc paths. Worker OffscreenCanvas is the primary renderer so framebuffer-heavy games
are not presented through an extra proxy copy; a main-thread proxy remains as the compatibility
fallback. The generated Emscripten Fetch glue is then patched from
vendor/ppsspp/range-read-ahead.js so ISO/CSO/CHD reads can consume up to two validated 2 MiB
blocks ahead without changing the pinned WASM. The pinned source plus those patches reproduce the distributed WASM files;
scripts/build-ppsspp.mjs is the canonical build entry point.

The Web runtime also links the FFmpeg submodule pinned by that PPSSPP commit
(1e3b4965632f60b1d85360261d1b9dd45444bc71). It is built as a minimal WebAssembly
decoder set for H.264, AAC, ATRAC3, ATRAC3+, and MP3. This is required for PSP PSMF/PMP
video; a build with USE_FFMPEG=OFF boots games but renders those videos as corrupt frames.
